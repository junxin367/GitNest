# Git 操作功能补齐

日期：2026-10-06，Asia/Shanghai。

本轮按用户选择实现功能，保留工作区已有未提交修改。用户排除文件任意多选、按变更块暂存、选择部分仓库批量同步，并在实现期间取消导航前进／后退；这四项均不包含在最终交付中。

## 操作入口与行为

| 入口 | 新增行为 |
| --- | --- |
| 变更页与 Stash 区域 | 保存全部修改或当前文件，填写备注，选择是否包含未跟踪文件；重命名的当前文件包含原、新路径。沿用已有恢复、恢复并删除及删除操作。 |
| 变更页提交操作 | Amend 预填 HEAD 说明并追加当前暂存内容；撤销最近提交支持保留暂存状态或取消暂存，两者保留文件修改。 |
| 变更页冲突区域 | 显示冲突文件、在外部编辑器打开、逐文件标记已解决；支持 Merge、Rebase、Cherry-pick、Revert 的继续／中止。 |
| 历史提交详情与右侧详情 | 实际执行 Cherry-pick／Revert，从精确提交创建分支，打开受支持托管站点的远程提交页面。 |
| 历史页筛选 | 在 Git 完整历史中组合查询说明／正文、作者、日期、字面文件路径；先筛选再分页，支持引用与引用对比。 |
| 侧栏创建菜单 | 初始化本地仓库、克隆仓库；显示进度，支持取消，完成后显式加入当前 Workspace。 |
| 仓库顶栏“远程与标签” | 添加、修改、删除远程地址；创建轻量或附注标签、删除本地标签、推送指定标签。显示目标路径，队列完成后自动刷新。 |

## 写操作与异步约束

- 新的工作流、远程与标签写操作加入现有仓库操作队列、取消和历史记录；IPC 校验动作、目标、路径、布尔确认与完整提交 ID。
- 写操作使用一次性预检，核验 Workspace、Worktree、HEAD、相关内容指纹与有效期。队列执行时再复核，旧确认不能直接写入新的仓库状态。
- Amend／撤销说明历史改写影响；已发布信息依据本地远程引用，并明确没有联网确认。继续冲突操作禁用交互编辑器，避免后台进程等待输入。
- 切换目标后丢弃旧请求结果，创建分支绑定选中的完整提交；历史条件变化重置分页，过期查询结果不能覆盖当前列表。
- 普通 UI 操作状态读取使用轻量检查，不生成完整 Diff、不读取全部未跟踪文件内容；完整内容指纹只用于写操作预检与复核。
- Clone 不覆盖非空目录，不递归清理失败现场；Windows 取消终止进程树，退出应用时取消并等待创建任务收尾。
- 创建完成后加入 Workspace 时携带 `expectedWorkspaceId`，后台在队列真正执行前检查，防止切换期间添加到错误的 Workspace；旧添加目录接口保持兼容。
- 标签推送拒绝多 Push 地址，全部远程地址参与预检；使用 `--no-follow-tags`，不会因用户 Git 配置而附带其他标签。

## 验证中发现并修复

1. Git for Windows 的 Stash 内部清理受全局 `--literal-pathspecs` 影响，可能保存成功但留下未跟踪文件；改为逐路径 literal pathspec，并验证原文件确实从工作区移除。
2. `git am` 与 Rebase 共用部分目录结构；增加明确识别，避免发出错误的 Rebase 继续／中止命令。
3. 远程地址读取首项不足以识别多个 Push URL；指纹纳入全部地址并限制标签推送目标。
4. Clone 取消及管理操作排队后的有效期复核补齐，并通过独立复核。

## 明确边界

- 不支持通过撤销入口移除初始提交；合并提交的 Cherry-pick／Revert 因需要选择主线暂不提供。
- 冲突编辑调用已有外部应用，不包含内置三方合并编辑器；进行中的 `git am` 提示使用对应终端命令完成。
- 远程提交链接支持 GitHub、GitLab、Gitee 公共站点；未知或自建托管站点返回明确提示。
- Clone 认证沿用系统 Git 凭据助手和 SSH 配置；失败或取消后保留目标目录供检查。
- 导航前进／后退已按用户后续指示完整撤销，保留原有导航。
