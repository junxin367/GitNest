# 文件忽略、文件历史与冲突流程

日期：2026-10-06，Asia/Shanghai。

本轮只实现用户选择的三项：忽略文件操作、文件历史与逐行追溯、冲突流程的跳过及空提交处理。沿用此前工作区修改；其他建议未纳入本轮。

## 入口与行为

| 入口 | 行为 |
| --- | --- |
| 主窗口和独立 Diff 的变更文件右键菜单 | 文件历史／逐行追溯；未跟踪文件额外提供忽略此文件、忽略所在目录、忽略同扩展名文件。根目录文件和无扩展名文件禁用不适用范围。 |
| 历史提交的文件 Diff | 从当前精确提交打开该文件历史。 |
| 忽略预览弹窗 | 展示实际规则、目标 `.gitignore` 与影响，确认后通过仓库队列追加，等操作成功后刷新列表。取消预览不写入。 |
| 文件历史弹窗 | 每页 50 条，固定首屏 revision；跟随 Git 检测到的重命名，显示历史路径和对应 Diff。按需读取所选提交的 Blame，可点击行的来源提交查看变更。 |
| 进行中的 Git 操作 | 显示当前重放提交；Rebase、Cherry-pick、Revert 支持跳过。已无文件变更时可跳过或保留空提交，避免重复点击继续。Merge 无跳过操作。 |

## 写入与异步约束

- 忽略操作只接受未跟踪普通文件，向当前 Worktree 根 `.gitignore` 追加，不删除文件、不取消跟踪、不自动暂存。
- 字面规则转义特殊字符，保留原文件字节、UTF-8 BOM 与换行风格；拒绝越界路径、符号链接、硬链接 `.gitignore` 和超大或非法编码文件。
- 一次性预检含有效期与文件指纹，确认时和队列执行时重新校验。已有 `.gitignore` 使用追加写入，缺失文件使用独占创建；预检后发生变化要求重新检查。
- 跳过与保留空提交沿用工作流预检、队列和取消机制。遇到提交范围外的修改或未跟踪文件会阻止跳过；保留空提交要求无冲突、无暂存或未暂存变更。
- 文件历史仅查询已提交对象，固定完整提交 ID；不执行外部 Diff 或 textconv。切换目标、文件、版本及关闭弹窗取消旧请求，迟到结果不能覆盖当前内容。
- 独立审查发现合并冲突解决提交漏列，已将历史与 Diff 的合并比较统一为第一父提交并补真实 Git 回归。
- 菜单回调保持稳定，提交说明输入不会触发全部文件行重新渲染，已有性能回归继续通过。

## 边界

- 根 `.gitignore` 规则仍可能被子目录的取消忽略规则覆盖；预览明确提示，不虚报最终匹配数量。扩展名规则也可能匹配同后缀目录。
- 重命名跟随采用 Git 检测结果。深分页使用有输出上限的前缀遍历后切页，避免 `--follow` 与 `--skip` 联用造成重复或遗漏。
- Blame 支持 UTF-8 文本，最大 1 MiB／10,000 行；历史、Diff 与 Blame 输出上限 8 MiB。二进制、删除版本、空历史及超限均明确提示，不展示伪造或截断的完整结果。
- 旧 `rebase --apply` 可以跳过，保留空提交需终端；`git am` 保持终端指引。内置三方合并编辑器不在本轮范围。
