# 页面交互与读取性能优化

日期：2026-10-06，Asia/Shanghai。

本轮优化现有功能的读取与渲染开销，保留此前未提交修改。修改前生产构建、相关源码和差异保存在 `temp/interaction-performance-20261006/before/` 与 `baseline.patch`。

## 实施项

| 场景 | 改动 |
| --- | --- |
| 文件历史在 Diff／Blame 之间切换，或 A → B → A | 对话框内部缓存完整提交 ID 对应的成功结果；路径及重命名两端进入键，关闭或切换作用域后清理。每种最多 12 项，Diff／Blame 估算预算分别为 4／8 MiB，超限结果不缓存。 |
| 文件历史追加、Blame 展开后续行 | 用 Set 去重，隔离历史列表、历史行与 Blame 行的渲染，复用未变化行；保留原来的每次 500 行渐进展示。 |
| 操作状态重复刷新 | 同一目标的并发只读请求合并；操作完成时使旧结果失效，并在必要时串行补一次新读取。换仓和完成事件不再各触发两次查询。 |
| 冲突操作区域不可见 | App 仅在仓库变更页启用自动状态读取；显式读取、严格预检以及后台操作完成反馈仍正常工作，重新进入页面后读取最新状态。 |
| 隐藏侧栏 | 不构造目标索引与筛选结果，不挂载仓库列表行；保留组件状态和独立确认弹窗。显示时使用最新数据，并在正确的布局阶段恢复滚动位置。 |
| 首次 Blame | `ls-tree --long` 一次取得对象 ID 与大小，减少一个 Git 进程；使用 porcelain 复用提交元信息，减少输出和解析工作。保留完整版本、路径、编码、二进制、大小和取消检查。 |

## 确定性工作量对照

这些是请求、格式化、数据读取及 DOM 数量，不是界面毫秒数。

- 同一组 Diff → Blame → Diff → B → A → Blame 交互：Diff 请求 **4 → 2**，Blame 请求 **2 → 1**。
- 50 条历史及 501 行 Blame 场景：追加 1 条历史的日期格式化 **1,103 → 1** 次；展开第 501 行时 **553 → 1** 次。
- 同一目标首次查询期间连续调用 10 次刷新：IPC 请求 **11 → 1** 次；换仓及操作完成各 **2 → 1** 次；操作记录重排／裁剪不再触发额外查询。
- 500 仓库隐藏侧栏：仓库行 **500 → 0**，DOM 节点 **8,082 → 41**；隐藏期间后台更新读取仓库、Worktree、Snapshot、目标四类记录各 **500 → 0** 次。重新显示时照常读取最新数据。

## 真实 Git 对照

固定仓库，每种文件预热一对，随后 12 对前后交替测量，所有返回内容逐项相同。

| 场景 | 修改前中位 | 修改后中位 | Git 进程数 |
| --- | --- | --- | --- |
| 3 行文本的 Blame | 252.8ms | 214.0ms | 5 → 4 |
| 6,000 行，含重命名及交错提交 | 524.8ms | 251.2ms | 5 → 4 |

大文件场景 Git 总输出从 2,424,300 降至 666,344 字节，约减少 73%。独立回归还覆盖同一来源提交内不同历史文件路径汇入合并结果，避免元信息复用造成逐行归因错误。

## 生产页面前后对照

固定 60 个真实 Git 仓库、2,000 行文件及 8 个历史版本，使用冻结的前后生产构建，3 对交替运行，每次独立 profile，共 180 个操作样本。统计从页面点击处理开始，到正确版本内容连续三帧可见的耗时；这是内容就绪与绘制机会近似值，不是硬件输入到屏幕显示时间或标准 INP。

| 场景 | 修改前中位 | 修改后中位 |
| --- | --- | --- |
| 同一版本切回 Diff（每版本 15 样本） | 181.3ms | 43.4ms |
| 同一版本切回 Blame（每版本 15 样本） | 415.8ms | 64.7ms |
| 返回已读版本 A（每版本 12 样本） | 397.3ms | 57.0ms |
| 返回已读版本 B（每版本 12 样本） | 402.8ms | 57.45ms |
| 隐藏侧栏（每版本 12 样本） | 45.45ms | 47.95ms |
| 重新显示侧栏（每版本 12 样本） | 42.15ms | 43.65ms |

重复历史交互约减少 76%–86% 的等待。侧栏切换耗时没有测得提速，收益为隐藏后 DOM **1,030 → 45**、仓库行 **60 → 0**，以及隐藏期间停止派生与渲染列表。首次 Blame 的聚合中位下降，但三轮波动大且第一轮更慢，不把它算作稳定的冷启动收益；不要将上面的后端 6,000 行读取结果泛化为所有页面首次打开耗时。

优化后每轮 **17 项生产界面检查通过，renderer errors 为 0**。覆盖快速切版本／标签后结果正确、完整展开 2,000 行、筛选保留、滚动至 650px 后隐藏、隐藏期间修改测试仓库并刷新、再次显示最新状态并恢复滚动、各类菜单隐藏后关闭。最终文件历史和滚动恢复截图已人工检查。

测量工具试跑遇到后台窗口计时节流以及旧内容短暂满足就绪条件，均在正式采样前修正；前后统一禁用后台渲染节流，并要求正确内容连续三帧成立。第一轮旧版在所有性能采样结束后暴露创建菜单隐藏仍残留的已有问题，原始失败记录保留；该轮性能样本完整有效，新版三轮均验证菜单正确关闭。

## 验证与限制

- 缓存只存在于当前文件历史对话框，不缓存可变 HEAD／短引用，不缓存错误或已取消结果；预算为估算内存，不宣称精确堆占用。
- Workflow 的既有 inspect IPC 没有取消协议；已发往后台的跨目标旧请求仍会结束，优化通过合并、串行及结果隔离减少工作，没有伪称取消底层进程。
- 隐藏侧栏减少后台成本，但重新显示仍需挂载完整可见列表；未实现列表窗口化。
- 所有写前预检、有效期、内容指纹及队列复核保持原有严格性。
- 定向验证覆盖错误重试、迟到结果、切目标／Workspace、隐藏期间终态、滚动和筛选恢复、菜单关闭、大小边界和逐行归因。
- `pnpm test`：136 个测试文件、**2,136 项全部通过**，用时 120.84 秒。类型检查、生产构建、架构边界及差异检查通过。
- 正式 Electron 测量与全量测试分开运行，避免相互争用。前后交替原始数据与汇总保存在 `app-smoke/*-results.json` 和 `app-smoke/comparison.json`。
