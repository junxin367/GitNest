# 仓库目录折叠、展开卡顿修复

日期：2026-10-06，Asia/Shanghai。保留工作区已有修改，没有提交。

## 原因与修改

1. `useWorkspace.setGroupCollapsed` 原先等待 IPC 持久化完成才更新 UI。现在立即叠加本地折叠状态；同组保存串行并合并中间点击，保证最后意图；失败回退并报告错误。期间广播仍更新选中仓库、监控等字段，旧保存响应只合并对应组的 `collapsed`。切换 Workspace 清理旧意图并隔离晚响应。
2. 分组折叠原先卸载所有仓库行，展开重新挂载。现在首次展开才创建行，后续使用 `hidden`/`inert` 保留并隐藏同一批 DOM；隐藏时仍接收真实仓库状态和筛选更新。切换 Workspace 不复用旧组的挂载状态。稳定行生成回调，无筛选时复用原 targets，行集合独立 memo。
3. 顶层 Workspace 目录原先对整个仓库树执行 240ms `grid-template-rows` 动画。现在直接切换隐藏状态，保留原有打开概览、键盘和选择语义。
4. “收起/展开所有分组”同时提交各组的本地意图，不再等前一组保存后才处理下一组；主进程继续按已有配置队列持久化。
5. 后端折叠保存原先重新读取 Workspace 列表并重建刷新调度目标、遍历快照。现在跳过无关列表读取，拓扑和选中目标引用不变时保留调度和快照；仍持久化、最终重读当前文档、更新摘要并广播。并发拓扑变化仍走完整路径。原路径未主动触发 Git 刷新，没有将此问题错误归因于 Git 命令。

## 性能对照

实际 Electron、生产 React、真实 `WorkspaceSidebar` 及完整生产 CSS，1,000 仓库。旧源码及 CSS 在修改前冻结。三对 AB/BA/AB，共 144 次开合，正式计时没有与全量测试或构建并发。明确使用 `prefers-reduced-motion: no-preference`，覆盖正常动画；每动作每版本 18 个观测。

| 中位数 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 分组折叠至 DOM 提交 | 10.55ms | 0.55ms |
| 分组展开至 DOM 提交 | 20.80ms | 0.60ms |
| 分组展开至首帧，含强制布局 | 89.75ms | 64.95ms |
| 顶层目录折叠视觉稳定检测 | 331.95ms | 65.00ms |
| 顶层目录展开视觉稳定检测 | 298.30ms | 98.65ms |
| 每次分组展开新建仓库行 | 1,000 | 0 |

组件夹具的回调即时返回，只测渲染，不代表磁盘/IPC 耗时。DOM 提交由 `aria-expanded` 的 MutationObserver 记录；视觉稳定包含连续三帧检测开销，不能当作纯绘制时间。

144 次操作的折叠状态、隐藏、inert、最终高度和节点复用断言均通过，renderer errors 为 0。六张最终截图内容一致，已人工查看。前后展开高度相同。

没有把所有指标写成改善：分组折叠首帧从 14.95ms 变为 23.85ms，视觉稳定基本不变。保留 DOM 减少重新挂载，但有内存代价，未量化堆内存。千仓库展开仍有约 45–50ms 浏览器布局成本；首次展开未挂载的分组也仍有创建开销，不能宣称任何规模下都完全无卡顿。
