# 代码节点按需加载

## 原因与改动

原页面切到代码节点后，会请求完整快照并在渲染进程为所有节点建立搜索索引，完成前禁用搜索并隐藏列表。即使只展示 120 个结果，也需要先传输全部节点。

- 导航快照附带首批 120 个节点，收到后即可显示和搜索；请求链保持原有加载方式。
- 新增 `nodes` 快照查询，后台对完整分析结果搜索，只返回前 120 个匹配结果和匹配总数。
- 选中节点时按需返回局部关系图，后台最多收集 400 个关系节点、800 条边；画布原有 160 节点、320 条边的显示限制继续有效，并显示截断提示。
- 后台按 512 项分片建立关系索引和执行搜索，分片之间让出事件循环；查询结果按分析快照缓存，最多保留 8 个搜索词。
- 列表查询期间保留已有内容，支持错误重试；请求序号、页面生命周期和分析结果身份共同防止旧响应覆盖新查询或其他 Workspace。
- 检查节点详情不会重新请求相同关系图；搜索结果更新但图布局不变时，保留拖动、缩放及节点位置。

- 最后调整查询触发和错误提示后，重跑页面、关系图及 hook 的 104 项测试，通过。
- 全项目类型检查、架构检查、生产构建及修改文件空白检查通过。
- Chrome 使用真实页面、真实 hook 和模拟 IPC（每次节点查询延迟 2 秒）：等待期间仍显示 120 行且搜索框可输入；搜索 `hiddenTarget` 返回首批之外的结果，选中后补齐 `remoteCaller → hiddenTarget`，全量快照读取为 0 次。返回导航后搜索与局部图仍保留。
