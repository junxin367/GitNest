# 代码分析页面切回空白修复

## 原因与证据

- 已确认：`App` 原来通过条件分支挂载分析页，切走即卸载。页面内部的 `useCodeAnalysis` 状态和快照随之丢失，返回时从空状态重新执行 `getState`、`getSnapshot`。
- 直接表现：页面无快照时整体替换为骨架，骨架的 180 ms 延迟期间由 CSS 隐藏，因此只有背景；之后等待重新读取结果。
- 对照：概览、仓库等页面的数据由 App 中的 workspace 控制器持有，不依赖分析页的局部状态。
- 防线缺口：此前有快照同步、身份校验和单页加载测试，但未覆盖真实切离/返回时的生命周期及第一帧内容。
- 排除：不是把骨架延迟取消就能保留内容的问题，也不是分析结果本身缺失；已经读取的数据在组件卸载后被丢弃。

## 修复

- 新增 `AnalysisPageHost`，首次访问后保留一个分析页面；隐藏时暂停 Effects，重新显示时恢复订阅并校验服务状态。
- 保留范围绑定 Workspace、根路径和参与分析的 Worktree 身份/路径；切换这些上下文会释放原页面。没有为每个历史 Workspace 累积缓存。
- 返回时服务结果身份未变化，直接复用完整快照，不重新读取导航摘要替换已有完整图；显式 `reload()` 仍执行完整读取及身份校验。
- 页面恢复不再重复初始化筛选、导航焦点、图缩放及布局；首次完整图请求若曾在隐藏时失效，恢复时可重新请求。

## 验证

- 3 个相关测试文件、101 项测试通过，涵盖首次未访问不读取、返回时立即保留内容、隐藏时解除订阅、结果变化时更新、Workspace/根路径隔离、筛选/滚动/缩放保留，以及原有快照身份防护。
- `pnpm typecheck`、`pnpm build`、`pnpm check:architecture`、修改文件的 `git diff --check` 通过。
- Chrome 使用真实页面、真实 hook 和真实保留容器，模拟 `getState` / `getSnapshot` 各 500 ms 延迟；旧条件挂载方式与修复后的保留方式对照：
  - 已加载后切走再回来，旧方式采样 22 帧中有 21 帧未显示内容，约 1379 ms 首次显示，并再次读取快照。
  - 修复后采样 51 帧全部显示内容，首个采样约 15 ms；只重新读取状态，快照读取累计仍为 1 次。
  - `caller` 筛选、120% 缩放在返回后保留。
- 截图：`temp/analysis-return-20261009/after.png`。

## 边界与未闭环项

- 上述时间来自固定延迟的浏览器夹具，不代表用户机器、真实 Git/IPC 或大型分析图的性能指标；它验证返回时不等待读取才显示内容。
- 首次访问还没有前端快照时保留原有加载行为；本次修复针对已显示内容后的切离/返回。
- 未重新生成安装包；未操作用户当前 Electron 窗口或真实工作区数据。
