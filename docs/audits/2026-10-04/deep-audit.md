## 已修复的确认问题

| 范围 | 触发及原行为 | 修复与证据 |
| --- | --- | --- |
| Git 与 MCP 只读查询 | 配置 `core.fsmonitor` 后，差异及新鲜度查询运行仓库脚本 | 在对应只读 Git 命令禁用 fsmonitor；真实临时仓库 hook 写 marker 先失败再通过，普通 Git 命令作为正对照 |
| Bare worktree | bare porcelain 记录合法地没有 HEAD，却被当作损坏输出 | bare 记录允许缺少 HEAD；真实 bare 仓库与 linked worktree 集成验证 |
| 远程分支 | 合法 `origin/feature/HEAD` 被后缀过滤掉 | 使用 `%(symref)` 识别符号引用；兼容旧字段格式，真实 Git 输出验证 |
| 工作区拓扑 | 同 commonDir 的后序离线 root 覆盖在线 root 新发现的 worktree，导致持久化校验失败 | 保留新扫描元数据并合并旧离线拓扑；两种 root 顺序、真实保存和重载验证 |
| 分析工作区切换 | A 的延迟 settings/hydration 回包可能覆盖 B，甚至启动旧分析 | 所有相关入口校验 selection 代次与身份；同时验证同一工作区并发初始化仍复用缓存 |
| 账户连接测试（未接入生产） | 孤立服务中更新凭据后，旧连接测试结果把新凭据标成已验证；未证实用户入口可达 | 写验证状态前检查凭据引用和连接身份；不计作用户产品故障 |
| LSP 消息分派 | 服务端请求与客户端 pending 请求使用相同数字 ID 时，被错误当作响应 | 先区分带 method 的请求；双向 ID 碰撞回归 |
| 多路由关系图 | 一个方法对应多个 route/method 时只保留最后一个端点 | 多端点使用独立节点并连接共享处理方法；保留单端点原有节点语义 |
| 增量结果完整性 | 截断的新结果继承旧结果的 complete 状态 | 截断时禁止提升完整性 |
| 增量边合并 | 新符号歧义已使 builtin 边失效，但合并又恢复旧边 | 仅保留仍有效的 LSP/merged 关系，不恢复被重建撤销的旧 builtin 边 |
| LSP 局部失败 | 单次语义请求失败、引用截断或复用不支持能力的会话后，仍标 complete | 传播内部 incomplete 状态并保留已拒绝能力状态；准确上限、去重与会话复用回归 |
| Worktree 请求忙碌状态 | 自动执行分支缺少 await，提前进入 finally，异常反馈也可能绕过 | 等待执行完成后清理；deferred 成功和失败回归 |
| Diff 加载状态 | 展开上下文时重选同文件，旧请求失效、新静默请求也不清 loading | 由当前有效请求清理；覆盖两种完成顺序 |
| Diff 内容刷新 | 相同文件刷新显示旧内容；展开后收起再刷新也有遗漏 | 区分真实改动与纯上下文响应，更新 compact 内容并失效旧展开状态；8 组真实 Git 补丁与 `git diff -U3` 对照 |
| Diff 连续符号 | hunk 内合法 `---`/`+++` 源码行误认成文件头，行号与配对错误 | hunk 内正确解析，文件边界独立重置；多文件及上下文扩展回归 |
| 设置多行输入 | 每次键入立即 trim/filter，Enter 换行被吞掉 | 编辑时保留原始行，保存时规范化；保存失败和新草稿不被覆盖 |
