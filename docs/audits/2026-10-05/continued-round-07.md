# 持续检查第 7 轮：MCP 取消注册的回读结果

## RCA 结论

- 状态：已确认。
- 用户触发：在设置中取消 GitNest MCP 注册；CLI remove 成功，后续 get 已读取不到该配置。
- 现象：返回给界面的消息却是“已执行注册命令，但未读取到配置。”；若 remove 没有实际删除，旧代码反而显示“已注册，重新启动 Codex 后生效。”
- 直接原因：注册与取消注册都调用相同的 verified=true 描述分支，该分支只描述注册成功或注册缺失。
- 根因：读取状态时丢失了用户请求的目标状态，无法区分目标为已注册还是已移除。
- 系统性根因：已有子进程集成测试只断言注册命令参数与 registered=true，没有验证取消注册后的消息。
- 因果链：设置取消注册 → 执行 mcp remove → 回读 mcp get → registered=false → 错误套用注册成功校验文案。

## 已排除解释

- 本机 Codex 配置或 CLI 版本差异：测试使用自建临时 fake CLI，注册记录只写入测试目录。
- 命令参数转义失败：原有带空格、括号、`&` 和 `%TEMP%` 的路径参数断言继续通过。
- UI 误用返回值：错误消息由主进程服务产生，测试直接验证服务返回；没有修改界面逻辑。

## 修复与防复发

- 描述结果时传入目标注册状态，普通查询仍不附加操作成功语义。
- remove 成功但 get 未读取到配置时返回“已执行取消注册命令，未读取到配置。”；移除后仍有配置返回对应的未完成提示。
- CLI remove 失败使用“取消注册失败”，避免混淆为添加配置失败。
- 扩展既有测试的操作序列及断言，没有新增永久测试文件。该文件 2 项测试全部通过。
