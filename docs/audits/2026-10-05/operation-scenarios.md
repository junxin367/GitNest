# 操作功能场景复查

本轮承接骨架与异步状态复查，重点核验写操作、预检确认、失败重试及切换上下文时的操作归属。以下只记录本轮新增发现。

## 已确认并修复

### 同一预检凭据被并发执行两次

仓库命令与 Worktree 命令在异步重新校验结束后才删除预检凭据。两个执行请求可以同时读到同一凭据，分别通过校验并重复入队。现在参数与确认检查通过后、第一次异步等待之前就消费凭据；并发的第二次执行被拒绝，要求重新预检。

两个现有服务测试分别模拟重叠执行：修复前各接受两次，修复后均只接受一次、只生成一个队列任务。未确认或参数不匹配的请求仍不会消费凭据。

涉及 `repository-command-service.ts`、`worktree-command-service.ts` 及其已有测试。

### Git 写入成功后刷新失败被当成写入失败

`useRepositoryMutations` 将写入与后续刷新放在同一个失败处理分支，提交成功后刷新抛错仍返回失败，导致界面保留可再次提交的信息。现在保留写入成功结果，并单独提示状态刷新失败；切换上下文后的旧结果仍不向当前调用者返回成功。

现有测试覆盖提交成功但刷新失败、重复调用拦截及失败后重试。

### 储藏操作的旧成功结果跨越页面切换

`useRepositoryStashes` 在异步 `finally` 刷新完成前已确定返回 `true`。刷新期间切换仓库或卸载，旧调用者仍可能收到成功并关闭后来打开的对话框。现在等待储藏列表与工作区刷新结束，再核对请求归属并返回结果。

现有测试分别覆盖两个刷新阶段中切换目标与卸载。

### 已撤销或跨上下文的确认回调仍可执行

仓库、单仓库 Worktree 和工作区 Worktree 的确认闭包保留旧预检对象。仅清空界面 state 不会使已捕获的回调失效。现在预检凭据同时保存在同步引用中，确认与关闭立即消费或撤销；执行入口校验上下文身份，切换或卸载使旧请求失效。

### 目录选择与取消结果晚到污染新页面

Worktree 原生目录选择、仓库及 Worktree 操作取消的异步结果原先未核对请求归属。现在切换上下文或卸载后丢弃旧路径与反馈，防止旧路径填入新操作表单或旧取消提示覆盖当前反馈。

### 入队成功至状态事件到达之间可重复提交

界面的 `busy` 状态不能替代命令入口的同步保护。现在接受操作后立即跟踪其操作 ID 与目标，在终态到达前拦截冲突的重复请求；终态和提交失败后释放保护，允许重试。仓库批量 Fetch 仍允许互不重叠的后续分块提交。

上述命令层修改限定于三个 command hook 与已有集成测试，没有改动 `App` 或 `RepositoryPage` 的批量操作入口。

全部写操作使用新建临时仓库、本地 bare 远端及独立 Electron 用户目录，未修改用户真实仓库的数据。

| 场景 | 操作入口 | 核验 |
| --- | --- | --- |

## 第二轮：批量部分失败、确认意图与精确路径操作

以下是在首轮 1381 条测试基线之后新增的发现与修复。

| 场景 | 原问题 | 修复 |
| --- | --- | --- |
| 批量命令的后续目标入队失败 | 已入队任务仍会运行，但调用方只收到异常，失去任务回执 | 返回已接受的操作 ID 与 `submissionError`；界面继续跟踪任务并保留部分失败提示，终态后允许重试 |
| 其他入口提交或变更分支 | 主进程状态已更新，概览、历史、分支页仍显示旧内容 | 当前页响应状态内容版本变化；刷新失败保留已有内容；切换页签与状态同时变化不重复查询 |
| 提交过程中 AI 返回新草稿 | 提交成功后无条件清空文本，丢失新草稿 | 成功回调携带实际提交的文本，只清理仍与之相同的草稿 |
| 放弃确认后路径的跟踪状态变化 | 旧的还原确认可能被解释成删除未跟踪文件 | 界面撤销已过期的文件确认；Main 在任何写入前核对明确确认的未跟踪路径集合，不匹配则整体拒绝 |
| 文件被同名目录替代，仅暂存原文件删除项 | Git 的 literal pathspec 仍递归匹配，连带暂存未选子文件 | 删除项使用仅更新已跟踪路径的命令；选中子文件时保留未选兄弟文件 |
| 目录被同名文件替代，仅暂存新父文件 | 隐式暂存未选子文件的删除 | 先核对相关删除项是否全被选中，部分选择拒绝，完整选择正常执行 |
| 对文件／目录替代仅取消父路径暂存 | 连带取消未选子路径；完整选择又可能因冗余路径报错 | 执行前检查受影响暂存路径均已选中，再折叠冗余路径参数 |

`discard` 请求新增 `expectedUntrackedPaths`，省略时只授权还原已跟踪文件；删除未跟踪文件需要明确列出路径。界面中的单文件和批量放弃均传递该字段，IPC 校验类型、唯一性和请求路径子集。两种跟踪类型变化都会在写入前被拒绝。

本轮没有将已有的重命名、空仓库、冲突、提交钩子、旧回调隔离等修复重复计为新增问题；这些场景随相关测试继续回归。

## 第三轮：操作归属、批量终态与失败后的真实 Git 状态

以下是在第二轮 1422 条测试基线之后新增的发现与修复。

| 场景 | 确认的问题 | 修复 |
| --- | --- | --- |
| 暂存或 Fetch 与切换工作区并发 | 两个工作区包含相同目标时，写操作登记前的异步空隙使切换检查放行；两者均被接受，操作在新工作区执行，原操作记录可能被重置 | 将操作接纳、队列尾登记与工作区切换串行化；Git 执行本身留在接纳队列之外，避免内部读取工作区状态时互相等待 |
| 批量命令先失败或取消、后成功 | 已完成任务从跟踪列表移除，后来成功的任务清除之前的失败或取消反馈；清除提示、取消剩余任务也可能丢失已有错误 | 在当前请求周期保留终态错误、取消结果及部分提交错误，后续成功不覆盖；新请求或切换上下文时重置 |
| 提交在钩子中被取消或超时 | 尤其在 `post-commit` 阶段，Git 已生成提交并清空暂存区，调用却只返回一般取消或超时错误，容易引导重复提交 | 失败后限时读取 HEAD，保留原错误码，并提示提交结果尚未确认、先核对历史与暂存区；HEAD 改变也不直接判定本次提交成功 |
| Stash apply/pop 发生冲突 | 命令失败时部分文件已应用，其他文件冲突，Stash 仍保留；原反馈缺少这些状态 | 失败后只读检查冲突路径和所选 Stash 引用，提示可能部分应用、引用检查结果及先解决冲突再操作 |

另外补齐两个 Hook 的入口保护：`useRepositoryMutations` 与 `useRepositoryStashes` 的旧回调在切换、A→B→A 或卸载后再次被调用时，不再发送旧目标 IPC。该问题由直接调用保留回调的 Hook 测试确认，属于边界保护；本轮没有将其表述为已经复现的普通界面点击路径。

## 第四轮：分批入口、页面反馈与 Git 钩子失败

以下是在第三轮 1446 条测试基线之后新增的发现与修复。

| 场景 | 确认的问题 | 修复 |
| --- | --- | --- |
| Workspace Fetch 超过 50 个目标 | App 逐批提交时忽略请求返回的 `false`，某批预检或部分提交失败后仍继续下一批 | 将分批调度提取至现有 settingsRuntime 模块，遇到未完整受理的批次立即停止；已接受任务仍继续被跟踪 |
| 不同批次的任务重叠运行 | 新请求或新回执会清空前批次错误；旧任务成功又可能覆盖新请求的提交失败 | 只在没有待跟踪任务的新请求开始时重置结果；统一保留终态错误、取消结果和各次提交失败 |
| 切换页面与旧任务终态同帧到达 | scope 清理后，终态 effect 仍从旧 state 读取任务，重新写入旧错误或完成计数，甚至调用新页面的 Worktree 刷新回调 | 三个 command Hook 仅处理当前范围仍拥有的已接受任务 ID |
| 在 Workspace 页面点击 Fetch／Pull／Push | 仓库命令错误没有传入概览或集合页面，预检失败时看不到原因 | 在 Workspace Header 接入现有命令提示，覆盖概览、仓库、活动和 Worktrees 页签；仓库详情仍使用原有提示，避免重复显示 |
| Git 失败后的恢复刷新期间点击取消 | 结束刷新后才判断取消信号，将已经发生的 Git 失败重写为取消并丢失原错误 | 在进入失败处理时记录 Git 结果，后续恢复读取期间的取消不改写该结果 |
| 创建 Worktree 的 post-checkout 钩子失败 | existing/new/detached 三种模式均可能已生成目录和登记，但只返回普通命令失败，直接重试碰到已有路径或分支 | 失败后限时检查 Worktree 登记，保留失败码并提示先核对现有目录及钩子结果 |
| 切换分支的 post-checkout 钩子失败 | 实际已切到目标分支，但只返回失败，容易重复切换 | 失败后检查当前符号引用和 HEAD，说明当前已选中的目标分支，保留原失败结果 |
