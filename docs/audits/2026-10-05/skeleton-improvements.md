## 显示规则

| 当前状态 | 显示方式 |
| --- | --- |
| 当前目标尚无可用数据，正在读取 | 对应页面或区域的骨架 |
| 当前目标已有数据，后台刷新 | 保留内容 |
| 已成功读取空结果，后台刷新 | 保留空态 |
| 请求结束且结果为空 | 立即显示空态 |
| 首次读取失败 | 显示错误与重试入口 |
| 仓库、工作区或选择目标变化 | 不复用不属于当前目标的数据 |

共享组件按 `loading && !hasContent` 判断，不再在请求完成后强制延长骨架时间。已加载空数组与尚未加载分开处理。设置、分析、分支、历史、stash、工作区侧栏和全局搜索补充了相应状态处理。分析状态已到达但快照仍在读取时，加载状态继续有效。

## 页面适配

- 页面入口的加载占位按当前视图选择概览、列表、设置、分析或变更布局。
- Diff 内容骨架跟随当前统一/左右对比布局；独立 Diff 初始加载使用用户设置。
- 设置和分析占位按容器宽度折叠列数，概览指标卡片使用现有设计令牌和容器断点。
- 共享骨架保留状态语义，补充温和播报属性；验证现有减少动画支持。
- 布局由页面类型和视图配置选择，并非从任意页面 DOM 自动推断。新页面仍需接入合适的占位布局。

## 第二轮复查与修复

针对首次提交、快速切换、刷新失败及请求被取代的情况继续检查：

- 分支、仓库页签、搜索重新打开：同步返回即将开始的加载状态，消除被动 effect 执行前的假空态。
- 独立 Diff：按当前文件路径和模式筛选可显示数据，切文件的首帧不再展示上一文件内容；Diff 已可用时不再被仍在加载的变更列表遮住。
- 独立 Diff 的加载完成标记只在成功后设置；首次失败重试、目标移除后恢复时重新展示骨架，恢复目标的首帧也经过验证。
- 同一文件的 Diff 刷新失败、已加载单文件列表刷新失败时保留内容并提示错误；分支和储藏增加不遮挡内容的重试提示。
- 仓库变更清空时取消旧 Diff 查询，避免加载状态残留和旧错误晚返回。
- 代码分析：重读时清除失效的快照请求标记及完整快照加载状态；缓存恢复计入加载；不匹配的响应不清空已有有效内容；成功重试清除其已解决的读取错误。

新增 28 条回归用例，全部位于既有测试文件。首次提交检查使用 layout effect 或 React Profiler，异步顺序通过受控 Promise 验证。设置失败重试、搜索刷新失败保留结果、储藏快速选择和侧栏空结果路径也进行了复核。

## 第三轮复查与修复

进一步覆盖局部内容、取消请求、缓存恢复与状态事件交错：

| 场景 | 修复 |
| --- | --- |
| 仓库变更首次查询已取消 | 骨架跟随实际 loading 结束，不再由“无内容且无错误”推断持续加载 |
| 提交详情自动选择首文件 | 首次提交即显示该文件的加载状态，不闪现手动选择提示 |
| 展开上下文期间重复选择同一提交文件 | 保留已有 Diff 和当前上下文范围 |
| 代码分析切节点或文件 | 源码与 Diff 按上下文标识隔离，首帧不泄漏旧内容；同 ID 的位置或 Worktree 变化重新读取 |
| 缓存恢复接口失败或请求被取代 | 与明确的缓存未命中区分，避免错误触发新的全量分析 |
| 多次缓存恢复交错、工作区变化或重读 | 旧响应不覆盖当前状态，也不结束新请求的加载 |
| 普通状态事件先于缓存恢复响应到达 | 独立跟踪恢复请求是否未完成，保持正确的加载和操作禁用状态 |
| 目标工作区数据先于切换命令响应到达 | 展示已经收到的目标内容，操作忙碌状态继续保留；旧工作区事件不会使骨架提前消失 |
| 媒体预览失败后切文件 | 解码失败与资源 URL、预览范围绑定，下一文件首帧不显示旧错误 |

同时核验同仓库状态刷新失败、历史分页失败、分页中切换分支比较、快速切换提交、储藏操作失败及同文件节点间复用。已有内容和当前请求归属符合预期，无需额外业务改动。
