# 持续检查第 1 轮：AI 大批量 Diff 读取与请求上限

## RCA 结论

- 状态：已确认。
- 用户触发：在含大量暂存文件的仓库点击生成提交信息；前几个文件已经超过聚合 Diff 的 120,000 字符预算。
- 现象：旧代码仍读取全部文件，并为每个省略的文件追加完整路径。1,000 个长路径文件的受控复现产生 348,909 字符用户消息，超过聚合正文预算。
- 直接原因：达到上限后的循环继续追加省略文件标题；所有 Diff 在截断前已经完整收集。
- 根因：预算仅约束单次正文截取，没有约束整个累积输出，也未反馈到读取调度。
- 系统性根因：既有测试覆盖暂存范围、连接配置和响应释放，没有覆盖大量文件时读取调度与请求体的共同上限。
- 因果链：生成入口 → 收集全部文件 Diff → 聚合预算耗尽 → 继续追加每个文件路径 → 读取成本和请求长度随文件数增长。

## 证据

| 判断 | 类型 | 证据 |
| --- | --- | --- |
| 聚合预算未限制最终正文 | 事实 | `temp/goal-ten-rounds/round-1/red.log`；新增既有测试失败，实际 348,909，大于 121,000 |
| 修复后预算耗尽停止后续批次 | 事实 | 同一测试断言 Diff 读取次数不超过 4、消息小于 121,000 字符、保留截断标记；`green.log` |
| 既有生成行为保持 | 事实 | `pnpm exec vitest run apps/desktop/src/main/ai/ai-commit-message-service.test.ts`：14 项通过 |

## 已排除解释

- API 服务拒绝或网络波动：测试以本地受控 fetch 捕获请求，失败发生于发出的用户消息长度。
- 单文件已有截断标识：复现文件没有单文件截断标记，问题由聚合路径和读取时机独立触发。

## 修复与防复发

- 按最多 4 个文件为一批读取并立即计入预算，达到预算后停止新批次。
- 将标题和分隔符计入预算，所有省略文件合并为一个聚合截断提示。
- 新增 4 条既有测试回归：首批超限、第二批超限及标题/分隔符精确计数、9 文件跨 3 批不超限（单文件截断开启/关闭）。用户返回的文件总数与截断状态保留原契约。

## 未闭环项与验证边界

- 没有向真实 AI 服务发送请求；测试覆盖服务生成入口、Git 读取调度和最终请求体。
- 当前批次最多仍会读取 4 个文件；单文件大小仍由 Git Diff 读取限制。没有宣称中断已经开始的同批读取。
- 工作区持久化、外部应用及其它主进程路径将在独立轮次继续检查。
