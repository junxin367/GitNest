# 持续检查第 4 轮：扫描文件符号链接的误报

## RCA 结论

- 状态：已确认（受控文件系统观察覆盖，原生文件 symlink 创建受环境限制）。
- 用户触发：扫描包含文件符号链接的 Workspace；链接可以指向根目录内或根目录外的普通文件。
- 现象：内部文件链接报 `DIRECTORY_UNAVAILABLE`，外部文件链接报 `OUTSIDE_ROOT_LINK_SKIPPED`，尽管并不存在需要扫描的目录。
- 直接原因：扫描器按 `symbolic-link` 分类尝试目录遍历和目录边界校验。
- 根因：Node 文件系统适配器把文件和目录符号链接映射成相同的可遍历入口，没有识别链接目标为普通文件的情况。
- 系统性根因：已有集成测试覆盖真实目录联接、路径授权和过期，没有覆盖文件链接进入仓库目录扫描。
- 因果链：读取目录 → 文件链接被标记可遍历 → 真实目标越界或 readdir 返回 ENOTDIR → 添加无关的扫描警告。

## 证据

| 判断 | 类型 | 证据 |
| --- | --- | --- |
| 当前测试进程不能创建文件 symlink | 事实 | `temp/goal-ten-rounds/round-4/red.log`：Windows EPERM；这是环境限制，不是产品失败证据 |
| 内部/外部文件链接均被误报 | 事实 | `red-controlled.log`：固定 readdir/realpath/stat 的链接观察，调用真实适配器与 WorkspaceScanner；2 项断言失败 |
| 修复分类后不产生误报 | 事实 | `green.log`：文件系统适配器与 WorkspaceScanner 两个既有测试文件 20 项通过 |

## 已排除解释

- Windows 创建链接权限：以独立日志记录并改用受控链接观察；没有把 EPERM 当作产品缺陷。
- 根目录不可访问：fixture 根目录及目标文件是真实可读的临时文件，失败仅来自文件链接的错误遍历。
- 目录链接应被忽略：现有真实 junction 测试和扫描器循环/越界保护测试继续通过；实现仍把目录目标保留为 symbolic-link。
- 持久化候选：检查现有原子写队列、legacy 快照迁移和空快照覆盖路径，未找到足以证明新的可达故障的证据，本轮未修改这些路径。

## 修复与防复发

- 在文件系统适配器读取到符号链接时查询目标类型，把普通文件目标标记为 file、其它非目录目标标记为 other。
- 目录链接保留原分类，解析失败的链接继续交给扫描器报告局部错误。
- 在既有文件系统测试中新增内部/外部文件链接 2 条回归。

## 未闭环项与验证边界

- Windows 当前进程无文件符号链接创建权限，未宣称完成真实文件 symlink 的操作系统集成验证。
- 链接观察通过受控 fs 结果注入，其余目录扫描流程调用产品实现。真实目录 junction 仍由既有测试覆盖。
- 没有修改工作区文件内容、真实用户目录或系统链接权限。
