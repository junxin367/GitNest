# Workspace Shell 功能需求记录

> 更新日期：2026-09-16
> 状态：M1、M2、M3、三轮最终硬化、1.0.0 总集成、储藏浏览/操作与全局变更文件搜索设计已同步

## FR-001：添加目录并自动扫描 Git 仓库

### 用户目标

一个 Workspace 可以包含多个同级顶层条目。用户可以通过文件夹选择器、手动路径或目录拖拽添加本地目录，软件自动识别该目录及其子目录中的 Git 仓库，并根据扫描结果分类和分组。

扫描过程只读取目录和 Git 状态，不修改文件，不执行 Fetch、Pull、Checkout、Clean 等 Git 操作。

### 示例目录

以 `D:\code\sc\sc_code` 为例：

| 相对路径 | 识别结果 | 页面分组 |
| --- | --- | --- |
| `.`（`sc_code` 自身） | Workspace 根目录本身也是 Git 仓库 | `原/根仓库` |
| `core` | 直接位于 Workspace 根目录下的独立仓库 | `原/根仓库`（默认分组名） |
| `svr\*` | 位于 `svr` 目录下的仓库 | `svr` |
| `web\*` | 位于 `web` 目录下的仓库 | `web` |
| `python\*` | 位于 `python` 目录下的仓库 | `python` |
| `tool\*` | 位于 `tool` 目录下的仓库 | `tool` |

### 自动分组规则

1. 根目录自身是 Git 仓库，且内部还有独立仓库时，顶层类型为 `Workspace 元仓库`。
2. 根目录自身不是 Git 仓库，但内部包含仓库时，顶层类型为 `Workspace 目录`。
3. 根目录自身是 Git 仓库，且内部没有其他独立仓库时，顶层类型为 `普通仓库`。
4. 即使根目录已经识别为 Git 仓库，也必须继续扫描其子目录。
5. Workspace 根目录仓库和直接位于聚合根目录下的子仓库统一放入默认分组 `原/根仓库`，例如 `sc_code` 与 `core`。
6. 位于更深层级的仓库，默认使用其相对路径的第一个目录作为分组名：
   - `svr\ScResSvr` → `svr`
   - `web\scportal` → `web`
   - `python\sc-video-cut` → `python`
   - `tool\ScCommJob` → `tool`
7. 分组名称默认取自真实文件夹名称，不依赖预先写死的目录列表。
8. 多个聚合目录和普通仓库作为同级顶层节点展示。
9. 顶层节点显示名称、类型标识和完整路径。
10. 分组标题显示仓库数量，并支持独立折叠和展开。
11. 仓库数量、路径和分组必须来自当前扫描结果，不能使用页面硬编码数据。
12. Workspace 的概览、仓库、活动和 Worktrees 页面只读取当前打开的顶层条目；仓库列表、标签数量、工具栏批量操作数量、活动记录与详情统计必须使用同一作用域，不能混入其他顶层条目的仓库。

### 路径和身份规则

- 完全相同的规范化绝对路径重复添加时定位已有条目。
- 不同本地路径始终是不同仓库实例，即使名称、Remote 和提交相同。
- Remote URL 不参与仓库去重。
- 共享同一 Git common directory 的 linked worktree 分别展示路径，但关联到同一本地仓库实例。
- 根目录重叠时，仓库显示在路径最具体的已添加根目录下。

### 基础扫描边界

- 必须排除仓库自身的 `.git` 内部目录。
- 不应把依赖、缓存或构建产物中的嵌套 Git 目录误识别为 Workspace 仓库。
- 发现非根级子仓库后默认停止继续扫描其内部。
- 默认不跟随指向所选根目录之外的符号链接。
- 扫描失败或无权访问的目录应单独报告，不能中断其他目录的扫描。
- 本次需求中的“自动扫描”仅负责发现和展示，不自动执行远程同步。

### 验收示例

选择 `D:\code\sc\sc_code` 后，仓库树至少应呈现以下结构：

```text
sc_code                         [Workspace 元仓库]
D:\code\sc\sc_code
├─ 原/根仓库
│  ├─ sc_code
│  └─ core
├─ svr
├─ web
├─ python
└─ tool

ordinary-repository             [普通仓库]
F:\projects\ordinary-repository
```

## FR-002：Workspace 持久化与自动刷新

- Workspace、顶层条目、顺序、显示名称、自动分组和折叠状态只保存到 GitNest 应用数据目录。
- 默认不在用户项目中创建 `.gitnest` 文件。
- 启动立即展示上次 Snapshot，随后后台重扫和刷新。
- 监听工作目录和 Git 元数据；外部终端、TortoiseGit、UGit 或 IDE 的操作也能触发刷新。
- 监听不可用时降级为低频轮询。
- 首版只允许修改顶层条目的显示名称和顺序，不支持任意移动自动分组中的仓库。

## FR-003：日常 Git 工作流

- 支持 Diff、Stage、Unstage、Commit、历史和提交详情。
- 提交详情展示该提交修改的文件清单、文件数量与增删统计；选择文件后在同一详情区域显示该文件相对父提交的只读 Diff，切换提交时默认选中该提交的首个文件。
- 支持按当前仓库和 Worktree 浏览 Git 储藏记录及其文件统计，并对明确选中的记录执行恢复、删除或恢复并删除。
- 支持 Fetch、`ff-only` Pull 和 Push。
- 支持分支查看、创建、切换、重命名和安全删除。
- Stage、Unstage 和 Commit 在用户明确点击后执行。
- Pull、Push、分支和其他高风险操作先执行状态预检。
- 预检结果使用短期有效且绑定命令参数的确认凭据；目标状态或影响集合变化时必须重新预检。
- 破坏性操作必须展示具体仓库、分支、路径和影响范围，并由用户二次确认。
- 首版不提供普通 Force Push、任意 Reset、Clean 或自定义 Git 命令。
- 批量操作拆为逐仓任务，允许部分成功并单独重试失败项。

### 全局搜索与变更文件定位

- 顶部全局搜索和 `Ctrl K` 命令面板同时搜索仓库、Worktree、分支、命令及当前 Workspace 内的变更文件。变更文件搜索覆盖相对路径、重命名前路径、仓库/Worktree 名称和“已暂存 / 未暂存 / 未跟踪”状态。
- 空查询保持仓库与命令的默认结果；输入关键词后，匹配的变更文件以独立分组置顶展示。同一路径同时存在 staged 与 unstaged 内容时，必须显示为可区分的两个结果。
- 打开搜索时只读取可能存在变更或状态未知的目标；确认新鲜且干净的仓库不重复运行 Git。读取并发最多为 4，单仓失败不阻断其他结果，关闭搜索、Workspace 变化或状态版本变化时取消并隔离旧请求。
- 已读取结果按 `Workspace + repositoryId + worktreeId + 状态版本` 缓存；状态版本变化后失效并重新读取，不能把旧仓库或旧 Worktree 的文件写入当前索引。
- 激活变更文件结果后，先确认目标仓库/Worktree 选择成功，再进入该目标的“变更”页，并按当前变更数据重新校验文件路径和 staged/unstaged/untracked 模式。
- 定位目标文件时清除旧的文件筛选，展开所属状态分组和树形祖先目录，滚动并聚焦文件行，同时显示对应 Diff。文件已消失时消费本次定位请求并保留当前最新的默认选择，不循环跳转。
- 搜索结果异步加入时通过稳定结果身份保留当前键盘选择，不能因新文件插入列表前方而让 Enter 激活另一个结果。

### Diff 上下文展开

- 变更块标题保持左键展开上下各 10 行、再次点击恢复默认 3 行上下文的快捷行为。
- 右键变更块标题时在指针附近打开单项上下文菜单。当前变更块已完整展开时只显示“恢复精简”，其他状态只显示“展开全部”；操作仅影响当前变更块。
- 变更块菜单必须限制在视口内，打开后聚焦唯一菜单项，并支持方向键、Esc、外部点击和滚动关闭；执行操作后焦点返回同一变更块标题。

### 储藏浏览界面

- 文件导航栏中的“储藏的变更”是固定入口，紧邻提交编辑区上方；即使当前工作区没有未提交变更，该入口仍必须显示。
- 点击入口后，右侧内容从现有 Diff 切换为储藏浏览器。储藏浏览器的根容器必须恰好包含两个直接窗格：左侧储藏列表、右侧所选储藏的文件列表，不额外插入第三个预览窗格。
- 左侧记录显示 `stash@{n}`、主题、时间和可用的文件/增删统计；右侧显示所选记录的提交哈希、元数据、文件筛选和文件统计。
- 右键储藏记录时先选中该记录，再在指针附近打开上下文菜单；菜单按“恢复”“删除”“恢复并删除”的顺序展示。菜单必须限制在视口内，并支持首次菜单项聚焦、方向键移动、Esc、外部点击、滚动、窗口失焦和尺寸变化关闭。
- “恢复”对应 `git stash apply`，将内容应用到当前 Worktree 并保留储藏；“删除”对应 `git stash drop`，只删除该储藏；“恢复并删除”对应 `git stash pop`，仅在恢复成功时删除储藏，发生冲突或应用失败时由 Git 保留储藏。
- 三项操作都必须在执行前展示确认对话框和目标 `stash@{n}`、主题及短哈希。“删除”和“恢复并删除”使用危险操作语义，明确说明删除不可撤销；确认或执行期间禁用菜单和重复提交。
- 首次打开时读取储藏列表；选择一条记录后才按需读取其文件，不能为列表中的每条储藏预取文件详情。
- 选择普通工作区变更文件时，必须退出储藏浏览并返回该文件的 Diff。行内 Stage、Unstage、Discard 及分组操作不视为文件选择，不应关闭储藏浏览。
- 切换视图时，原有 Diff 和提交编辑器保持挂载；提交草稿、Diff 搜索条件、滚动位置及其他瞬时状态不得因打开或关闭储藏浏览而丢失。
- 储藏列表为空、所选储藏无文件、文件筛选无匹配、列表加载中、文件加载中和读取失败均有独立状态；失败状态提供重试，刷新时避免用空白界面替换仍有效的数据。

### 储藏数据与并发规则

- 储藏数据严格绑定当前 `repositoryId + worktreeId`。切换仓库或 Worktree 时，不得显示或复用其他作用域的列表、选择、错误或加载结果。
- 每次列表或文件读取都使用独立 `queryId`；新的同类请求、作用域切换和组件卸载必须取消旧请求，并通过请求代次/当前请求校验隔离迟到响应。
- 储藏的稳定身份是不可变提交哈希。`stash@{n}` 只作为显示标签和 Git 查询选择器，外部创建、删除或重排储藏后可能变化。
- 刷新列表时优先按哈希恢复选择；文件响应中的哈希必须与发起选择时记录的哈希一致。不一致时拒绝展示并提示重新读取，避免把重排后的 `stash@{n}` 内容错误归到旧记录。
- 列表读取使用 `getStashes`，所选记录的文件读取使用 `getStashFiles`；如果后续提供储藏单文件 Diff，则使用可选的 `getStashDiff`，不得改变当前“两窗格列表 + 文件列表”的默认结构。
- 文件统计覆盖 tracked、staged 和随储藏保存的 untracked 文件。untracked 内容必须相对其独立父树计算，不能误报为大量删除；二进制文件显示“二进制”，不伪造文本增删数。
- `limit` 必须有上限；`stashRef` 只接受精确的 `stash@{非负整数}`；路径、上下文行数和 mutation 请求必须经过 IPC 校验，并以参数数组调用 Git，禁止拼接成 shell 命令。
- 储藏 mutation 请求必须同时携带 `stashRef` 和列表读取时得到的完整 `stashHash`。执行前重新解析 `stashRef`，只有当前哈希仍与 `stashHash` 一致才允许继续；不一致时拒绝操作并要求刷新，不能因外部新增、删除或重排储藏而作用于错误记录。
- 储藏 mutation 通过现有 Worktree 写操作串行通道执行。无论 `apply`/`pop` 成功或失败，都重新读取工作区状态，因为冲突或部分应用可能改变索引和工作区；成功后重新读取储藏列表，并按哈希保留仍存在的选择，否则选择相邻记录。
- 操作结果通过现有通知体系反馈。`pop` 冲突时必须明确说明工作区可能包含待解决冲突且原储藏仍被保留。
- 本范围不创建或清空全部储藏，也不提供任意 stash ref、shell 参数或批量删除入口。

### 储藏浏览验收

1. 工作区干净时仍能从固定入口打开已有储藏。
2. 右侧储藏浏览器始终只有储藏列表和文件列表两个直接窗格。
3. 打开储藏列表只执行一次有界列表查询；选择记录后才读取该记录文件。
4. 外部重排 `stash@{n}` 后，刷新按提交哈希恢复正确记录；哈希不匹配的迟到文件响应不会显示。
5. 快速切换记录、仓库或 Worktree 时，已取消或迟到的响应不能覆盖当前界面。
6. 点击工作区变更文件返回其 Diff；点击 Stage、Unstage、Discard 等行内控件保持储藏视图。
7. 开关储藏视图后，提交草稿、Diff 搜索和滚动位置保持不变。
8. tracked、staged、untracked、二进制、空列表、空文件、筛选无结果、加载、错误和重试场景均有自动化覆盖。
9. 右键任意记录会选中该记录并显示三项菜单；菜单可通过键盘操作，且在 Esc、外部点击、滚动和窗口变化时关闭。
10. “恢复”应用内容但保留储藏；“删除”移除储藏但不应用内容；“恢复并删除”成功时应用并移除，冲突或失败时保留储藏。
11. 外部重排后，携带旧 `stashRef + stashHash` 的 mutation 被安全拒绝，目标工作区和其他储藏不被误操作。
12. mutation 成功后储藏列表与工作区同步刷新；应用失败或冲突后工作区仍刷新并展示可处理的真实状态。

## FR-004：混合认证

- 默认复用用户现有 Git Credential Helper、SSH Agent、`.ssh/config` 和仓库 Git 配置。
- 提供 GitNest 账号中心，支持 GitHub、GitLab、Gitee 和自建 Git 服务的 HTTPS Token。
- Token 首次录入时只短暂存在于受控表单并单向提交给 Main，随后保存到 Windows 安全存储；它不进入前端全局状态、普通 JSON、IPC 返回值、Git 参数、日志或遥测。
- 支持主机默认账号和仓库级账号覆盖。
- SSH 只使用系统已有身份，不导入或保存私钥与私钥口令。
- OAuth、MR 和 Issue 平台集成不属于首个正式版本。

## FR-005：Worktree 与外部终端

- 支持 Worktree 创建、Lock/Unlock、Move、Repair、Prune 和安全移除。
- Primary Worktree 不允许移除。
- 首版不允许强制移除脏 Worktree。
- Prune 只清理失效 Git 登记，不删除仍存在的目录。
- Worktree 路径可以位于 Workspace 根目录之外，但必须由用户选择或位于已配置根目录下。
- Worktree 写操作先预检；Move、Prune、Remove 等有明显影响的操作展示精确路径并二次确认。
- 支持在当前仓库或 Worktree 中启动 Windows Terminal、PowerShell、CMD、Git Bash 或用户配置的外部终端。
- 首版不实现内置终端。

## FR-006：交付里程碑

- M1：桌面框架、目录添加、扫描分组、持久化、缓存和状态聚合。
- M2：日常 Git 工作流、混合认证、操作队列和外部终端。
- M3：完整 Worktree 管理、恢复、迁移、日志、Windows x64 安装包和便携压缩包。
- 三个里程碑均可独立运行；全部完成后发布首个正式版本。
- 首个正式版本不启用自动更新，待发布渠道和代码签名方案确定后再接入。
